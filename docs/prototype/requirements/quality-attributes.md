# Сценарии качества OCR-модуля

| Сценарий | Условия и воздействие | Требуемая реакция | Измерение / проверка |
|---|---|---|---|
| Заменить OCR | Другой адаптер того же порта | Соседние стадии и схема полей сохраняются; ограничения возможностей проверены | TEST-OCR-010, TEST-OCR-019 |
| Ограничить дорогой вход | Растр или каскад достигает лимита | Остановка, сохранение только завершенных данных и очистка | TEST-OCR-002, TEST-OCR-016 |
| Не испортить читаемое поле | Хороший вход передан в новый профиль | История операций и измеренный переход правильности | TEST-OCR-009, метрика порчи |
| Отказаться от догадки | Номер закрыт, ФИО читается | ФИО сохранено, номер отсутствует с точной причиной | TEST-OCR-014 |
| Не смешать документы | Два документа в кадре | Кандидаты и поля раздельны | TEST-OCR-004 |
| Воспроизвести выбор | Проверяющий получил разрешенный набор результатов | Пересчет метрик без OCR и восстановление решения | TEST-OCR-020, TEST-OCR-023, TEST-OCR-025 |
| Защитить данные | Ошибка на персональном документе | Без реквизитов в общих логах, с ограниченным доступом к материалам | TEST-OCR-021 |

Сценарии раскрывают [требования SRS](SRS.md). При конфликте улучшения средней точности с неподдержанной выдачей и ресурсным ограничением применяется заранее зафиксированный [критерий качества](../product/acceptance-criteria/AC-OCR-002-quality.md). Общий весовой балл без явных жестких ограничений не используется для приемки.
