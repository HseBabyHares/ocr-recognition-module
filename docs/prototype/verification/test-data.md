# Корпус и правила разметки

## 1. Единица данных

Основная запись эксперимента качества OCR – один растровый кадр. Для входа из контейнера сохраняются source_id, page_index, параметры и версия растеризации; все страницы и производные одного физического документа остаются в одной группе. Контрактные испытания Prepare дополнительно используют исходные контейнеры из разрешенного перечня. Запись кадра имеет `sample_id`, `group_id`, ссылку на изображение, контрольную сумму, источник происхождения, способ получения, размеры, состав объектов и разметку видимости. Реквизиты человека не используются в идентификаторах файлов и открытых таблиц.

Один физический документ и его фотографии, сканы, обрезки и искажения объединяются в группу. При известной связи нескольких форм одного человека они входят в одну группу разделения, чтобы одинаковые ФИО и номера не попадали одновременно в разработку и итоговую проверку. Контрольные суммы выявляют точные дубликаты; группировка происхождения выявляет неточные.

## 2. Состав

| Категория | Набор случаев |
|---|---|
| Поддерживаемые формы | Старая карточка, АДИ-РЕГ 2019, АДИ-РЕГ 2023 |
| Представления | Фотография и скан, разная исходная детализация |
| Геометрия | Четверти оборота, EXIF, малый наклон, перспектива, частично видимые края, сгиб |
| Качество | Размытие, смаз, блик, пересвет, тень, контраст, шум, сжатие, перекрытие |
| Поля | Читаемые, отсутствующие, нечитаемые, конфликтующие гипотезы; редкие ФИО и несколько дат на форме |
| Кадры без цели | Фон, другие документы и похожие прямоугольные объекты |
| Несколько объектов | Два целевых документа; целевой и посторонний документ |
| Технические входы | Повреждение, неправильный заявленный тип, превышение байтов/пикселей, неподдерживаемые каналы |

Несколько целевых документов и поврежденный файл не размечаются как кадр без цели. Для них предусмотрены отдельные ожидаемые исходы. Снимки с экрана и сильная кривизна выделяются в самостоятельные пограничные категории; поддержка автоматической обработки заранее не утверждается.

## 3. Разделение корпуса

| Часть | Назначение | Ограничение |
|---|---|---|
| Разработка и обучение | Настройка алгоритмов, матрицы OCR-ошибок, словарей и моделей | Использование известно разработчику |
| Выбор вариантов | Сравнение кандидатов и гиперпараметров до фиксации | Не является окончательным свидетельством качества |
| Калибровка | Отображение score и выбор порогов принятия | Не используется для смены основной модели без нового разделения |
| Независимая проверка | Проверка зафиксированного выбора и критериев | Не используется для настройки после просмотра |
| Регрессия | Известные дефекты и граничные случаи | Может входить в разработку, независимость не заявляется |

Группы не пересекают первые четыре части. При недостатке данных допустимо групповое перекрестное сравнение внутри разработки и выбора; финальный резерв остается отдельным. Все синтетические производные наследуют группу родителя. Пропорции определяются доступным корпусом и требуемой точностью оценки, без произвольного фиксированного числа фотографий.

## 4. Разметка изображения и объекта

Для каждого объекта указываются форма, ее различимость на данном кадре, видимая область, углы с маской видимости и видимые области трех целевых полей. Невидимые углы не дорисовываются разметчиком как наблюдаемая истина. Для частичного документа может быть известна форма по чистому оригиналу, но отдельное поле `form_identifiable` отражает возможность определить ее именно по данному кадру.

Разметка дефекта указывает тип, область и связанное поле. Общая категория Q1–Q4 используется только как дополнительная страта: Q1 – качественный вход, Q2 – типичные условия, Q3 – сложные, Q4 – пограничные/непригодные. Читаемость отдельных полей задается независимо. Уровень качества системы не является эталоном самому себе.

## 5. Разметка поля

Для поля фиксируются `applicable`, `present=true | false | unknown`, `readability=readable | unreadable | disputed`, видимый текст, нормализованное значение при однозначном чтении и координаты. `present=false` допустим только при доступной области поля; `unknown` применяется, когда по кадру невозможно установить наличие значения. Пустые применимые и неприменимые поля образуют отдельные категории оценки. Значение, известное по другому оригиналу, хранится отдельно от наблюдаемого на тестовой фотографии.

Если цифры закрыты бликом, известный номер не превращает поле в читаемое. Выдача этого номера по догадке учитывается как неподдержанная выдача. При частичном кадре доступные поля оцениваются, недоступные получают собственную метку; снимок целиком не исключается ради улучшения метрики.

Критичные значения и читаемость проверяются вторым человеком. Спорные случаи разрешаются до фиксации корпуса. Если решение недоступно, пример получает `disputed` и заранее установленный режим анализа; его число и причина остаются в отчете.

## 6. Сравнение строк

Политика сравнения имеет версию. Для номера допустимо удалить только согласованные форматные разделители, сохраняя 11 цифр и ведущие нули. Для даты используется однозначный календарный разбор. Для ФИО можно отдельно считать строгую метрику и метрику с нормализацией регистра/пробелов, если она задана до запуска. Обе сохраняют различие букв, письменностей и U+0401/U+0451. Словарное исправление эталона и предсказания не является нормализацией сравнения.

## 7. Синтетика и реальные данные

Синтетика используется для контролируемых искажений, редких граничных случаев и открытой проверки контракта. Генератор, шаблон, параметры и семя сохраняются. Разделение одних и тех же шаблонов и имен проверяется отдельно; обучающий генератор не должен скрыто воспроизводить итоговые образцы.

Результаты синтетики и реальных изображений выводятся отдельно. Процент на синтетике не переносится на реальный поток. Публичные бенчмарки и возможное совпадение данных с обучением готовой модели указываются как ограничение сравнения, если происхождение известно.

## 8. Защита и изменение эталона

Рабочий манифест содержит только сведения, допустимые при распознавании. Закрытая разметка хранится отдельно и доступна оценщику. Реальные документы используются только в разрешенном режиме; автоматического накопления из рабочего сервиса нет.

Изменение эталона сохраняет причину, проверяющего, старую и новую версии. Предсказания не переписываются. После просмотра независимой проверки новая настройка требует нового независимого испытания либо явного ограничения вывода. Ошибки корпуса не скрываются удалением строк из готового результата.
