# Контракт вызова OCR-модуля

## 1. Назначение и версия

Проект схемы обозначен `ocr.module/1`. Он описывает программные операции OCR-модуля; пути HTTP, загрузка файла конечным пользователем и статусы заданий СИРД здесь не определяются. Общая схема данных находится в [модели данных](../data/data-model.md). Транспортная оболочка обязана сохранить ее смысл.

## 2. Общий контекст

| Поле | Тип | Смысл |
|---|---|---|
| `contract_version` | Строка | Версия схемы операции |
| `request_id` | Непустая строка | Корреляция внешнего обращения |
| `attempt_id` | Непустая строка | Конкретный вызов; не дает права изменять долговечное задание |
| `limits` | `ExecutionLimits` | Конечные пределы текущего вызова |
| `material_access` | Разрешенный адаптер доступа | Позволяет прочитать только переданные материалы |

`ExecutionLimits` содержит положительные конечные `timeout_ms`, `memory_limit_bytes`, `max_input_bytes`, `max_input_pixels`, `max_total_pixels`, `max_output_pixels`, `max_pages`, `cpu_threads`. Счетчики `max_model_calls` и `max_variants` являются целыми неотрицательными числами. `max_variants` ограничивает число дополнительных вариантов изображения сверх основного; ноль отключает дополнительные варианты. Нулевой бюджет вызовов модели допускается для подготовки без модели, но несовместим с обязательной стадией OCR.

Неуказанный обязательный предел, отрицательное или неограниченное значение отклоняется как `INVALID_CONFIGURATION`. `max_input_pixels` ограничивает страницу, `max_total_pixels` – суммарное число подготовленных пикселей вызова. Для разных операций может применяться более строгий поднабор; суммарный расход не обнуляется при внутреннем повторе.

Относительный бюджет переводится в срок по монотонным часам процесса. Ожидание модели входит в бюджет. Перенос между процессами не использует численное значение чужих монотонных часов.

## 3. Prepare

```text
Prepare(PrepareRequest) -> PrepareResponse
```

`PrepareRequest`: общий контекст, один `SourceFile`, `InputPolicy`. Политика задает `policy_id`, `policy_version`, `accepted_media_types`, разрешенные декодеры, параметры растеризации для контейнеров, пределы битности/каналов, правило ориентации и допустимость частичной подготовки. Имя файла не является проверкой типа. Обязательная поддержка конкретного контейнера не предполагается без соответствующей записи политики и проверенного декодера.

`PrepareResponse` содержит `pages[]`, `page_count` либо null при невозможности определить количество, `preparation_complete`, `diagnostics` и `applied_execution`. Каждый элемент `pages` имеет `page_id`, нулевой `page_index`, `source_id`, `status=prepared | failed | not_processed`, `prepared_artifact` либо null и причину ограничения. Для подготовленной страницы возвращаются размеры, цветовой порядок, технические свойства и цепочка учета ориентации. Обычный растр дает одну страницу с индексом 0.

При известном числе страниц сохраняется запись для каждой из них. Если разбор файла прерван до определения их числа, фиксируются доступные индексы, `page_count=null`, `preparation_complete=false` и причина. Частичный результат разрешен только политикой; при общем отказе материалы не передаются дальше. Политика не назначает предметную форму и роль страницы. Текстовый слой контейнера не подменяет OCR; скрипты и вложения не исполняются.

Поврежденная либо пропущенная страница не должна исчезать из результата бесследно. Поиск на успешно подготовленной странице возможен, однако отсутствие цели на ней не доказывает отсутствие цели во всем неполностью подготовленном файле.

## 4. Probe

```text
Probe(ProbeRequest) -> ProbeResponse
```

`ProbeRequest`: общий контекст, `page_id`, ссылка на ее подготовленный растр, `DetectionPlan`. План задает разрешенные методы поиска, набор форм, версию модели, необходимые диагностические признаки и конечный бюджет. Эталонная форма и углы не входят в запрос.

Ответ содержит `SearchResult`, гипотезы форм каждого кандидата, технические ограничения анализа и фактически примененную конфигурацию. `not_detected` требует `analysis_complete=true`. Слабые основания либо незавершенный анализ дают `uncertain`. Несколько кандидатов сохраняются раздельно; их ранжирование не дает автоматического разрешения смешать поля.

## 5. ExecuteProfile

```text
ExecuteProfile(ExecuteRequest) -> ExecuteResponse
```

`ExecuteRequest`: общий контекст, `page_id`, подготовленный растр этой страницы, выбранный `candidate_id` и его наблюдения, `CompiledExecutionSpec`. Спецификация содержит:

| Поле | Содержание |
|---|---|
| `spec_id`, `spec_version`, `spec_hash` | Идентичность неизменяемой спецификации |
| `form_id`, `profile_id` | Выбранная форма и профиль, полученные от вызывающей стороны |
| `targets` | Список запрошенных полей из поддерживаемой схемы |
| `stages` | Упорядоченные стадии и разрешенные повторные переходы |
| `implementations` | Идентификаторы адаптеров, версии, контрольные суммы моделей, устройство |
| `parameters` | Геометрия, параметры OCR, обработки полей и исправлений |
| `validation_rules` | Правила и области применимости локальных проверок |
| `stopping_policy` | Условия продолжения, частичного результата и остановки |
| `calibration_refs` | Применимые объекты калибровки либо пустой список |
| `retention_policy` | Режим промежуточных материалов в данном вызове |

Вся спецификация разрешается до запуска: неизвестные стадии, отсутствующие модели, циклы без предела и неподдерживаемые обязательные выходы отклоняются. Изменение профиля во время исполнения не изменяет уже принятый вызов.

Ответ содержит `candidate_id`, `form_id` из спецификации, диагностику согласованности формы, OCR-наблюдения, кандидаты и результаты полей, материалы, измерения качества, `applied_execution`, затраты и причину ограничения. При нормальном завершении каждый элемент `targets` имеет FieldResult. При остановке поля, которые не запускались, получают `not_processed`; результаты незавершенной стадии не принимаются.

Форма из запроса не является независимо измеренным предсказанием формы. При оценке поиска используются сохраненные результаты Probe, а при сквозном эксперименте выбор профиля выполняет объявленное правило по этим наблюдениям.

## 6. Общий ответ и ошибки

`operation_status`: `ok | partial | failed | cancelled | limit_exceeded`. Технический `ok` означает завершение операции по ее контракту. Он не доказывает, что найден СНИЛС или верно прочитаны все поля. В результате сохраняются `request_id`, `attempt_id`, `applied_execution`, `diagnostics`, `timings` и типизированный выход операции.

| Код | Значение | Поведение |
|---|---|---|
| `INVALID_INPUT` | Поврежденный или неразрешенный файл | Без поиска и полей по недоступному входу |
| `INPUT_LIMIT_EXCEEDED` | Превышен предел входа | Контролируемый отказ до дорогостоящих стадий |
| `INVALID_CONFIGURATION` | Неразрешенная или неполная спецификация | Исполнение не начинается |
| `CAPABILITY_MISMATCH` | Обязательный выход не поддержан адаптером | Без искусственного восстановления возможности |
| `MATERIAL_UNAVAILABLE` | Разрешенный материал недоступен | Без скрытого чтения другого источника |
| `MODEL_UNAVAILABLE` | Нужная модель отсутствует | Без замены через публичный API |
| `EXECUTION_LIMIT_EXCEEDED` | Исчерпан бюджет | Только завершенные материалы и поля |
| `CANCELLED` | Вызывающая сторона отменила работу | Завершение и очистка |
| `EXECUTION_ERROR` | Внутренний технический отказ | Без объявления отсутствия документа |

Диагностики поиска и чтения (`target_not_detected`, `form_ambiguous`, `multiple_candidates`, `partial_visibility`, `insufficient_resolution`, `field_unreadable`) находятся в выходе предметной стадии и не заменяют технические коды.

## 7. Полномочия и повтор

Источник передается через разрешенный адаптер доступа. Произвольный URL или путь из распознанного текста не используется для чтения. Материал и выбранный кандидат должны принадлежать одному входу и странице. Проверяется контрольная сумма прочитанных байтов.

Повтор вызова выполняет вычисление заново либо использует явно разрешенный проверяемый кеш. Модуль не гарантирует единственную публикацию при сетевых повторах: это обязанность вызывающего сервиса. Побитовая идентичность материалов проверяется отдельно от равенства нормализованных полей. `request_id` не используется как самостоятельный ключ доступа.

Материалы Prepare и ExecuteProfile, возвращенные по ссылке, сохраняются в области, предоставленной вызывающим адаптером. Ссылка содержит условия доступности и срок действия. Очистка временной памяти операции не удаляет переданный результат до освобождения его вызывающей стороной либо истечения объявленного срока. Для цепочки Prepare → Probe → ExecuteProfile используется общая разрешенная область материалов; это область хранения изображений, без состояния долговечного задания. Если гарантировать ее доступность нельзя, операция завершается MATERIAL_UNAVAILABLE вместо выдачи уже недействительной ссылки.

## 8. Совместимость

Изменение обязательности, типа или смысла поля требует новой версии схемы. Добавление диагностик и необязательных сведений допустимо только при способности потребителя сохранять неизвестные коды без ложного принятия результата. Схема OCR-модуля явно отображается адаптером в схему СИРД; совпадение имен полей не считается доказательством совместимости.
