# Потоки обработки и эксперимента

## 1. Интеграционный вызов

СИРД в схеме – внешняя вызывающая сторона. Между Probe и ExecuteProfile она принимает решение по наблюдениям; никакая транзакция ее базы внутри модуля не описывается.

```mermaid
sequenceDiagram
    participant C as Вызывающий адаптер
    participant M as OCR-модуль
    participant R as OCR-движок
    C->>M: Prepare(источник, политика, пределы)
    M-->>C: Подготовленный растр или ошибка
    C->>M: Probe(растр, план поиска)
    M-->>C: Кандидаты, гипотезы и ограничения
    alt Выбран кандидат и профиль
        C->>M: ExecuteProfile(кандидат, спецификация)
        M->>R: Чтение подготовленной области
        R-->>M: Исходные наблюдения
        M->>M: Извлечение, кандидаты исправления и проверки
        M-->>C: Поля, происхождение, диагностика, затраты
    else Нет надежного выбора
        C->>C: Обработать отрицательный или неопределенный результат
    end
```

При техническом отказе новая операция не предполагается автоматически. Повторы назначает вызывающая сторона, учитывая причину. Внутреннее повторное чтение поля регулируется пределами исполняемого профиля.

## 2. Эксперимент

План и предсказания фиксируются до сопоставления с закрытым эталоном.

```mermaid
sequenceDiagram
    participant P as План эксперимента
    participant X as Исполнитель
    participant M as OCR-модуль
    participant S as Результаты
    participant E as Оценщик
    P->>X: Список пар, профили, ресурсы
    loop Каждая запланированная пара
        X->>M: Рабочие операции с заданным вариантом
        M-->>X: Результат либо техническая причина
        X->>S: Запись пары и фактические измерения
    end
    S->>E: Полный набор предсказаний
    E->>E: Сопоставить с отдельно доступным эталоном
    E-->>S: Метрики и область вывода
```

Для компонентного сравнения разрешенные эталонные входы явно записываются как `assistance`. Результат такого сравнения не подменяет оценку сквозного пути. При пересчете метрик вызовы OCR отсутствуют.
