# Контракт экспериментального запуска

## 1. План запуска

`ExperimentPlan` передается автономному исполнителю. Обязательны:

| Сведение | Состав |
|---|---|
| Идентичность | `experiment_id`, `plan_version`, `plan_hash` |
| Назначение | `mode=end_to_end | component | replay_metrics`, исследуемая стадия и измеряемый эффект |
| Корпус | Версия манифеста, перечень sample_id, контрольные суммы изображений, назначение раздела данных |
| Варианты | `variant_id`, базовый вариант, полная спецификация стадий и параметры |
| Порядок | Предварительно сформированный порядок пар, семя перемешивания, число повторов |
| Ресурсы | CPU, потоки, память, ускоритель, бюджеты и режим кеша |
| Измерения | Версия протокола, метрики, границы сравнения и правило технических неудач |
| Запись | Каталог вывода, политика доступа и хранения, режим промежуточных изображений |

Манифест, доступный рабочему исполнителю, не содержит правильные поля, форму или углы. В компонентном режиме разрешенные подстановки перечисляются в `assistance`; сквозной запуск требует пустого списка.

## 2. Спецификация варианта

До обработки разрешаются все ссылки на адаптеры и модели. Сохраняются контрольные суммы весов и кода, параметры по умолчанию, язык, ограничения декодирования, правила извлечения, коррекции, нормализации и калибровки. Недоступная реализация получает причину недопуска; исполнитель не подставляет другую реализацию.

Для параметров, которые не влияют на предсказание, но влияют на измерение, также сохраняются значения: число потоков, параллельных процессов, прогрев, размещение данных и включение кеша. Каждое изменение формирует другой вариант либо другую аппаратную конфигурацию.

## 3. Запись результата

Каждая запланированная пара `(sample_id, variant_id, repeat_id)` получает одну терминальную запись `SampleRunRecord`.

| Поле | Содержание |
|---|---|
| `run_id`, `sample_id`, `group_id`, `variant_id`, `repeat_id` | Идентичность записи |
| `mode`, `assistance`, `test_doubles` | Режим и фактические подстановки |
| `input_hash`, `resolved_spec_hash`, `applied_execution` | Воспроизводимая конфигурация |
| `status` | `ok`, `partial`, `failed`, `cancelled`, `limit_exceeded`, `not_run` |
| `reason`, `failed_stage` | Причина технического исхода либо отсутствия запуска |
| `module_result_ref` | Сохраненный ответ, если он сформирован |
| `stage_records` | Операции, длительности, вызовы, завершенность и ссылки материалов |
| `wall_time_ms`, `cpu_time_ms`, `peak_rss_bytes`, `gpu_peak_bytes` | Ресурсы; отсутствие измерения – null с причиной |
| `cache_hits`, `warmup_state` | Отличие прогрева и переиспользования |

Перечень запланированных пар сохраняется отдельно. Завершенность проверяется сопоставлением с ним; исчезнувшая строка не считается успешным результатом и блокирует итоговый расчет. Повторный запуск создает новый repeat_id, сохраняя предыдущую неудачу.

## 4. Метрики и решение

`EvaluationRecord` содержит хеши предсказаний и эталона, версию оценщика, политику сравнения текста, метрику, страту, единицу анализа, числитель, знаменатель, значение либо null, интервал либо причину его отсутствия. Технические исходы, неоцененные страты и исключения перечисляются явно.

`SelectionRecord` содержит условия допустимости, все сравнивавшиеся варианты, результаты отсечения по каждому ограничению, недоминируемые варианты и правило окончательного выбора. Запись формируется по сохраненным метрикам и правилу выбора. Новое ограничение после просмотра результатов требует новой постановки сравнения.

## 5. Повтор и пересчет

Повтор OCR использует исходный манифест и разрешенную спецификацию. Пересчет метрик использует сохраненные предсказания без загрузки OCR-модели. Оценщик отклоняет несовместимую версию схемы, потерянную запись, неверную сумму или неуказанную подстановку. Подробная процедура – в [протоколе экспериментов](../../verification/experiment-protocol.md).
